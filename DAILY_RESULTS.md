# Результаты разработки NormDoc2JSON по дням

Журнал выполненных работ по семидневному спринту ИНГРО.ТЗ.02-2026.
Задачи и распределение ролей определяются таблицей 2 ТЗ.

Для каждого дня дополняем результаты обоих программистов, состояние интеграции,

и окружению. Новые проверки записываем с фактической командой и результатом.

## День 1 — Проектирование и каркас

Проверена ветка `day1`, коммит `e765b00`, включающий работу обоих программистов.

### Выполнено

- Программист 1 подготовил пакет `normdoc2json`, окружение и Format Router.
  Маршрутизатор определяет формат, кодировку текстовых источников, типы страниц
  PDF и доступные сведения о DPI изображений.
- Подготовлены 11 стартовых файлов в `tests/fixtures/router/` и 6 фотографий
  учебных карт в `tests/fixtures/phone_photos/`.
- Программист 2 добавил Pydantic-схему, каркас CLI и логирование в `norm_importer`.
  CLI принимает одиночные файлы и каталоги, поддерживает параметры OCR,
  строгий режим и путь журнала.

### Проверки и сверка с ТЗ

- Все 27 тестов маршрутизатора, схемы и CLI прошли.
- Маршрутизатор обработал 17 образцов из двух каталогов fixtures.
- Pydantic-схема приняла пример из Приложения А с матрицей 9×9 и двумя
  поправочными коэффициентами.
- Проверены запись JSON, журнал и код завершения `1` в строгом режиме
  для результата, требующего ручной проверки.
- Общий прогон с исключением `tests/test_v2_pipeline.py` дал 46 passed.
  На момент проверки полный сбор тестов останавливался из-за отсутствия openpyxl.

### Замечания по итогам проверки

- Схема принимает диапазоны неправильной длины и с обратным порядком границ.
  Строка `-2--1` обрабатывается с потерей знаков.
- Пакетный CLI перезаписывает результаты файлов с одинаковой основой имени.
- Pydantic и Typer отсутствуют в общем файле зафиксированных зависимостей.
- CLI формирует каркасную карту. Подключение маршрутизатора и извлечения
  данных к конвейеру ещё предстоит.

Эти замечания зафиксированы на указанном коммите. Закрытие каждого замечания
следует дополнить ссылкой на исправление и результатом повторной проверки.

## День 2 — Офисные документы и электронные таблицы

### Программист 1

Реализация подготовлена в ветке `day2_programmer1`.

- Добавлен публичный интерфейс `extract_spreadsheet` для XLSX, XLS и CSV.
- Восстанавливаются горизонтальные и вертикальные объединения, включая
  многоуровневые шапки. Сохраняются координаты от A1 и исходные диапазоны слияний.
- Извлекаются все листы, числовые значения, нули, пустоты, заголовки и примечания.
- Для XLSX сохраняются формулы и читаются их кэшированные результаты.
  Отсутствующий кэш и ошибки Excel дают предупреждения и флаг ручной проверки.
- CSV поддерживает разные кодировки, автоопределение или явное указание
  разделителя, кавычки, переносы внутри полей и строки разной длины.
- Ошибка отдельного листа сохраняется в диагностике, обработка остальных
  листов продолжается.
- Добавлены зависимости openpyxl, et_xmlfile, xlrd и тестовая библиотека xlwt.
- Исправлены типы списков, координат XLSX и преобразования дат XLS после
  замечаний Pylance. Повторная проверка самим Pylance не выполнялась.
- Добавлен `pytest.ini` с `pythonpath = .` для импорта пакетов при запуске
  тестов через команду `pytest`.

Подробный контракт API и сверка с ТЗ приведены в
[описании работы программиста 1](normdoc2json/DAY2_PROGRAMMER1.md).

### Проверки

Добавлены 17 тестовых случаев для парсеров, объединений, координат, формул,
кодировок CSV и обработки ошибок. Проверено на Windows с Python 3.14.7.

Обе команды из корня проекта в активированной `.venv` дали **63 passed**:

```powershell
pytest -q --ignore=tests/test_v2_pipeline.py
python -m pytest -q --ignore=tests/test_v2_pipeline.py
```

`git diff --check` прошёл. Полный сбор тестов проекта останавливается
из-за отсутствия scipy, необходимой существующему `test_v2_pipeline.py`.
