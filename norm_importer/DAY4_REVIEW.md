# Проверка дня 4: ошибки семантического разбора

Дата проверки: 21 ноября 2026 года. Проверенная версия: ветка `day4`, коммит `5ae6f95`.

Все три замечания относятся к работе программиста 2: разбору шапки, формул и условий применимости. Они не относятся к предобработке изображений программиста 1. Ниже зафиксировано поведение проверенной версии; исправления в рамках проверки не вносились.

## 1. Разбор шапки не подключён к Excel

**Место:** `norm_importer/cli.py`, функция `_parse_spreadsheet_file`, создание `NormCard` (строка 87 проверенной версии).

Функция `parse_card_header` импортирована, но не вызывается при обработке электронных таблиц. Вместо результатов разбора в карту записываются фиксированные значения. Отчёт `DAY4_PROGRAMMER2.md` при этом заявляет, что интеграция выполнена.

### Пример

Файл `sample.xlsx`, лист `Карта 43 Точение`:

| Диаметр D, мм | 25 | 50 |
| --- | --- | --- |
| 20 | 0,85 | 0,90 |
| 30 | 0,92 | 0,97 |

Ожидается извлечение номера карты и операции из названия листа, например:

```json
{
  "card_id": "SAMPLE_CARD_43",
  "applicability_conditions": {
    "operation_type": "Точение"
  }
}
```

Фактически при проверке получено:

```json
{
  "card_id": "SAMPLE_SHEET_01",
  "card_title": "Карта (Карта 43 Точение)",
  "applicability_conditions": {
    "operation_type": "Механическая обработка"
  },
  "calculation_formula": "Ttbl"
}
```

Для этого примера `requires_manual_review` равен `false`, список предупреждений пуст. Формула `Ttbl` также жёстко задана в коде: формулы из шапки листа не передаются в семантический разбор. В приведённом примере отдельной формулы нет, поэтому сам по себе `Ttbl` здесь не является ошибкой; пример подтверждает потерю номера карты и операции.

**Последствие:** числовая таблица может быть извлечена корректно, но семантические поля остаются шаблонными без предупреждения.

**Что исправить:** выделить название листа и строки шапки, вызвать `parse_card_header`, передать полученные поля в `NormCard`. Добавить сквозной тест XLSX с номером карты, операцией, условиями и явной формулой.

## 2. При извлечении материала теряется твёрдость

**Место:** `norm_importer/header_parser.py`, `MATERIAL_PATTERNS` (строка 33 проверенной версии).

### Пример

Вход:

```text
Материал: Сталь 170...210 HB, резец Т15К6
```

Ожидается сохранение материала вместе с ограничением твёрдости, например:

```json
{
  "material_group": "Сталь 170...210 HB",
  "tool_material": "Т15К6"
}
```

Фактически:

```json
{
  "material_group": "Сталь",
  "tool_material": "Т15К6"
}
```

**Причина:** после названия материала регулярное выражение использует ленивый захват `{0,45}?`, а обозначение твёрдости сделано необязательным. Совпадение успешно заканчивается сразу после слова `Сталь`.

**Последствие:** ограничение твёрдости исчезает из условий применимости. Если потребитель выбирает норматив по извлечённым условиям, он может применить карту к материалу за пределами исходного диапазона твёрдости.

**Что исправить:** сохранять описание материала и распознавать значение или диапазон твёрдости с обозначением шкалы. Допустимо хранить твёрдость в согласованных дополнительных параметрах, но она не должна теряться. Добавить проверки полного значения, а не только наличия названия материала.

## 3. У двустороннего ограничения L/D теряется нижняя граница

**Место:** `norm_importer/header_parser.py`, функция `extract_surface_and_accuracy`, выражение `ld_match` (строка 90 проверенной версии).

### Пример

Вход:

```text
Карта 43. Точение чистовое, 3<L/D<=10
```

Исходное условие: отношение длины к диаметру строго больше 3 и не больше 10.

Ожидается сохранение обеих границ и знаков сравнения. Например, при сохранении текущего строкового представления:

```json
{
  "extra_params": {
    "ld_ratio": "3<L/D<=10"
  }
}
```

Фактически:

```json
{
  "extra_params": {
    "ld_ratio": "<=10"
  }
}
```

**Причина:** регулярное выражение ищет только `L/D`, знак сравнения и число справа. Левая часть `3<` не захватывается.

**Последствие:** деталь с `L/D = 2` не соответствует исходному условию, но соответствует сохранённому `L/D <= 10`. Область применимости карты ошибочно расширяется.

**Что исправить:** поддержать односторонние и двусторонние ограничения, сохраняя обе границы и строгость сравнений. Добавить тесты для `3<L/D<=10`, `L/D>3`, `L/D≤10` и десятичных границ.

- Ошибки материала и L/D воспроизведены прямым вызовом `parse_card_header`; ошибка Excel — вызовом `_parse_spreadsheet_file` на временной книге с указанным выше листом и таблицей.

Текущие тесты не выявляют эти ошибки: проверка материала требует только наличия названия, тест с `3<L/D<=10` не проверяет полученное `ld_ratio`, а интеграция парсера шапки в Excel отдельным тестом не покрыта.

Для закрытия замечаний нужно исправить реализацию, добавить проверки перечисленных примеров и повторить регрессионный прогон. Прохождение существующих 101 теста само по себе не подтверждает устранение этих дефектов.
