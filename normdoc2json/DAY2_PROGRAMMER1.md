# Результат второго дня программиста 1

Ветка `day2_programmer1`. Основание — таблица 2 ТЗ ИНГРО.ТЗ.02-2026,
задача первого программиста второго дня: парсеры XLSX, XLS и CSV
с восстановлением объединённых ячеек. Реализация находится в `spreadsheets.py`.

## Реализованный интерфейс

`from normdoc2json import extract_spreadsheet`

`extract_spreadsheet(path, delimiter=None)` использует Format Router для
проверки типа файла и определения кодировки CSV. Возвращает
`SpreadsheetExtraction` с полями `source_file`, `source_format`, `sheets`,
`warnings` и свойством `requires_manual_review`.

Каждый `SheetGrid` содержит имя листа, прямоугольную сетку `values`, список
`merged_ranges` и словарь `formulas`. Индексы в диапазонах и ключах формул
начинаются с единицы. Границы диапазонов включительные. Сетка начинается
в A1, поэтому пустые строки и столбцы перед таблицей сохраняют координаты.
Пустые ячейки имеют значение `None`, числовой ноль сохраняется.
Значение верхней левой ячейки распространяется на весь объединённый диапазон.
Это восстанавливает многоуровневые шапки и вертикальные объединения.
Сами диапазоны сохраняются для различения исходных и восстановленных значений.
Текст заголовков и примечаний сохраняется на исходных позициях.

XLSX читается через openpyxl, XLS — через xlrd. Читаются все листы,
включая скрытые. XLSX сохраняет исходные формулы и использует их кэшированные
результаты. Отсутствующий кэш и ошибки Excel дают `None` и предупреждение
с координатами. Пересчёт формул не выполняется. XLS предоставляет сохранённые
значения через xlrd, исходные формулы этот API не возвращает.
Даты Excel представлены объектами datetime, логические значения — bool.

CSV поддерживает разделители `;`, `,`, табуляцию и `|`, кавычки и переносы
строк внутри полей. Разделитель можно задать явно. При неудаче автоопределения
используется `;` с предупреждением. Строки разной длины дополняются `None`.
Числовые строки CSV, включая десятичную запятую, сохраняются буквально для
семантического разбора без потери кодов и заголовков.

Ошибка отдельного листа записывается в стандартный Python logging и `warnings`,
после чего обработка других листов продолжается. Ошибка открытия книги,
повреждённый файл и неподдерживаемый формат вызывают `InspectionError`.
При интеграции `warnings` и `requires_manual_review` нужно перенести в
`source_metadata` выходного документа.

## Сверка с ТЗ

| Требование | Результат |
| --- | --- |
| Таблица 2, XLSX/XLS/CSV | Реализованы три парсера через единый публичный интерфейс |
| Таблица 2, объединённые ячейки | Восстанавливаются горизонтальные и вертикальные диапазоны |
| Извлечение сетки с координатами | Сохраняются позиции от A1 и границы объединений |
| Пустые ячейки и диагностика | `None`, предупреждения с координатами, флаг ручной проверки |
| Пункт 8.1, публичный API | Русские docstrings |

Результат является промежуточной сеткой для семантического парсера.
Выделение карт, осей, числовой матрицы и правил из примечаний, экспорт по
Приложению А и подключение к CLI относятся к последующей интеграции.
CLI этой ветки всё ещё создаёт каркасную карту первого дня.
ODS остаётся обязательным форматом спринта по общему перечню ТЗ и требует
отдельного парсера. В задаче первого программиста второго дня он не перечислен.

## Проверки

Установка и запуск из корня репозитория:

```powershell
.\.venv\Scripts\python -m pip install -r requirements-normdoc2json.txt
.\.venv\Scripts\python -B -m pytest -q tests/test_spreadsheet_extraction.py
```

Добавлены 17 тестовых случаев. Они проверяют XLSX и настоящий бинарный XLS,
многоуровневые шапки, слияния, несколько листов, исходные координаты, нули,
пустоты, примечания, CSV в UTF-8 BOM/CP1251/UTF-16 с тремя разделителями,
кавычки и переносы, явный разделитель, неровные строки, повреждённый файл,
кэш формул, отсутствие кэша, ошибки Excel, даты, продолжение после ошибки
листа и имеющийся пример `turning.xlsx`. xlwt используется для тестовых XLS.

Итоговый прогон `pytest -q --ignore=tests/test_v2_pipeline.py` — 63 passed,
включая все 17 новых случаев. `git diff --check` прошёл.
Проверено на Windows с Python 3.14.7. Полная сборка тестов проекта требует
дополнительной зависимости scipy для существующего `test_v2_pipeline.py`.
Linux, Python 3.10, нормативная точность на контрольном наборе и показатели
скорости/памяти из ТЗ требуют отдельных приёмочных испытаний.
