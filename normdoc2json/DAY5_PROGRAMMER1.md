## Что реализовано

- Адаптер Tesseract TSV: языки, тайм-аут процесса, исходный текст, координаты слов и confidence от 0 до 1. OCR работает локально после установки моделей.
- Потоковое чтение растров и многостраничного TIFF; постраничная растеризация PDF в 300 DPI. Гибридные страницы растеризуются целиком один раз, поэтому текстовый слой не дублируется.
- Коррекция перспективы по выраженной четырёхугольной рамке таблицы. После неё повторный deskew отключается, чтобы фон фотографии не менял ориентацию таблицы.
- Поиск замкнутых ячеек, восстановление строк, столбцов и объединений. OCR содержимого ячеек выполняется на составном изображении, с дополнительной попыткой для пропущенных фрагментов.
- Ошибки отдельной страницы не останавливают последующие. Низкая уверенность, нераспознанный текст, повреждённые границы и отсутствие сетки отражаются в предупреждениях.
- Мост в существующий семантический маппер и Pydantic-модель; CLI подключён для изображений, TIFF, сканированных и гибридных PDF. Нераспознанная числовая ячейка становится `null` с исходным текстом и адресом в диагностике, а не отклоняет всю карту.
- `--debug-images` сохраняет изображения с рамками и промежуточный JSON с координатами, исходными значениями и уверенностью.

## Установка и автономная работа

Python-зависимости уже входят в `requirements-normdoc2json.txt`; дополнительная Python-обёртка для Tesseract не нужна.

На Windows установить Tesseract, например:

```powershell
winget install --id UB-Mannheim.TesseractOCR --exact
.\.venv\Scripts\python -m normdoc2json.setup_ocr
```

На Ubuntu установить системный пакет `tesseract-ocr`, затем выполнить `python -m normdoc2json.setup_ocr` из корня проекта. Linux в этой проверке не запускался.

Скрипт скачивает `rus.traineddata` и `eng.traineddata` из официального репозитория Tesseract с меткой 4.1.0 в `.ocr_models`. Записывает URL и SHA256 в локальный `manifest.json`. Модели исключены из Git. После установки сеть для OCR не нужна.

Можно задать каталог моделей через `INGRO_TESSDATA` или аргумент `TesseractEngine(tessdata=...)`. Исполняемый файл ищется в PATH и стандартном каталоге Windows; для другого расположения доступен `TesseractEngine(executable=...)`.

## Запуск

Из корня `ingro_dfm`:

```powershell
.\.venv\Scripts\python -m norm_importer.cli -i scan.pdf -o result.json --ocr-lang rus+eng --strict --debug-images
.\.venv\Scripts\python -m norm_importer.cli -i scans -o results --strict
```

При `requires_manual_review` строгий режим возвращает код 1, даже если JSON сохранён. Если ни одной карты извлечь нельзя, выбрасывается диагностическая ошибка, фиктивная нормативная карта не создаётся. Повреждённый вход также не создаёт JSON с выдуманными данными.

Отладочные файлы CLI находятся рядом с источником в `<имя файла>.debug`. Программный API позволяет явно задать другую папку.

```python
from normdoc2json import iter_ocr_pages, ocr_document

for page in iter_ocr_pages('scan.tiff', debug_dir='debug'):
    print(page.page_number, page.confidence, page.warnings)
    for table in page.tables:
        print(table.values, table.merged_ranges)

document = ocr_document('scan.pdf')
document.to_json_file('result.json')
```

## Контракт передачи программисту 2

`OCRPage`: источник, номер страницы от 1, таблицы, слова вне таблиц, предупреждения и средняя уверенность слов страницы.

`OCRTable`: прямоугольник таблицы, `values`, `cell_bboxes`, `confidences`, `merged_ranges`. Значения — исходные строки или `None`; объединённые значения распространяются на покрытые позиции. Диапазоны объединений имеют индексы от 1 и включительные границы. Confidence ячейки — минимум по её словам; пустая ячейка имеет `None`.

`OCRWord`: текст, прямоугольник, confidence, идентификатор строки OCR. Все координаты относятся к подготовленному изображению после коррекции перспективы, масштаба и наклона. Это пиксели, не пункты исходного PDF. Обратное преобразование к исходной странице не предоставляется.

Семантическая обработка примечаний программиста 2 не перенесена из его ветки. Мост `ocr_document` сохраняет окружающий текст в предупреждениях и отмечает необходимость семантической проверки. `notes_and_coefficients` остаётся пустым. Для интеграции следует использовать исходные блоки и координаты, а не разбирать строки предупреждений.

## Ограничения

- Таблицы без замкнутой сетки и повреждённые границы могут не восстановиться; выдаётся предупреждение, уверенная структура не выдумывается.
- Некоторые шапки фотографий распознаются неоднозначно. В частности, интервальная шапка карты 02 требует доработки семантического маппера; валидность JSON не означает правильность интерпретации её осей.
- Все шесть фотографий требуют ручной проверки. Числовая точность 100% не отменяет предупреждения по остальному содержимому.
- Коррекция перспективы эвристическая и всегда помечается для проверки.
- Лимит 40 млн пикселей предотвращает чрезмерную растеризацию/масштабирование, но не является гарантией общего расхода памяти. Для больших TIFF ограничения декодирования Pillow также остаются существенными.
- Обработка 200 страниц, Linux, Python 3.10 и импорт в расчётное ядро не проверены. Это отдельные проверки к сдаче спринта.
- Два старых теста `test_v2_pipeline.py` используют отсутствующий абсолютный путь `D:\Antihrafity\FW\Ingro\ingro_dfm\test_passport.json`; они не исправлялись в рамках OCR.
